# Doc API · 产品操作手册（测试发布版）

> **Doc API** 是一个文档结构化提取平台：从一份国家模板出发，用 prompt 自迭代不断打磨「字段识别规则」，
> 把任意票据 / 文档变成一个稳定、可用 API-Key 调用的提取 API。
>
> 本手册面向**测试同事**，覆盖三类角色：**平台管理员**、**用户管理员（租户）**、**普通用户**。
> 版本：测试发布版（2026-06）。线上地址：**https://invoicase.cn**

## 1. 一句话理解产品

**你不写识别规则，你只「改字段 + 传样本 + 给反馈」，平台自动把规则迭代到稳定可用。**

```
国家模板 → 客户改字段/给反馈 + 上传样本并人工确认 → prompt 自迭代（最多 3 轮，单调不降）
        → 激活发布 → 用 X-API-Key 调用的稳定提取 API
```

- 数据驻留：OCR 用境内合规模型（阿里云百炼 qwen3-vl-plus 视觉 + qwen-plus 文本）。
- 多租户：用户只看本租户的数据；平台管理员跨租户全可见。

## 4. 核心流程：定制一个提取 API（租户视角）

> 主线。目标：把一份国家模板，定制成贴合你票据的稳定提取 API。

### 步骤 1 · 新建 API
首页「定制新 API」→ 选国家模板（如 MY 马来西亚发票 / JP 日本发票）→ 系统按模板生成初始字段集，进入**工作区**。

### 步骤 2 · 编辑字段（工作区「字段视图」）
- **改名 / 改描述**：双击字段进入编辑面板。
- **新增字段**：「添加识别字段」→ 填字段名 + 样例值，系统用 LLM 反思扩展出识别规则。
- **删除字段**：字段右侧删除图标（全样本 + 优化器同步生效）。
- **改类型 / 格式（客户 override）**：如发票号设为 `number` + 去特殊符——**持久化、跨反思存活、压过国家模板通用常识**。
- **🔒 国家锁定字段**：国家模板声明的锁定字段（当前 MY/JP 各 4 个：发票号码 / 开票日期 / 开票方名称 / 开票方税号）
  **不可增删改**，识别钉死国家规范、不参与反思优化。
- **字段反馈提示**（新）：每个字段可填一句「用户反馈」，喂给下一轮迭代反思——详见 [§6](#6-字段级用户反馈)。

### 步骤 3 · 上传样本并「已审视」（含噪声样本门）
1. 上传 **3 张精选「锚点」样本** → 逐张核对识别结果，每个字段确认 / 修正后点「**已审视**」。
   被审视 / 修正的值即成为 **Ground Truth（人工真值）**，是迭代的训练信号。
2. **3 张锚点审视完成后**，横幅提示「即将启动自动迭代优化，请额外上传 **9 份多样化噪声样本**」：
   - 点「批量上传 9 份噪声样本」→ 弹窗**一次性多选**，计数器要求**正好 9 张**才激活上传；
   - 噪声样本（不同开票方 / 版式 / 税率 / 扫描质量，越随机越好）**自动以当前 OCR 为基线、无需逐张复核**，
     作为**留出验证集**，让优化更稳健、不过拟合那 3 张；
   - 凑满 3 + 9 = **12 张** → 自动启动 3 轮迭代。
3. 样本不足时停在「等待样本」，补足后自动继续。

> 为什么要 9 张噪声：3 张精挑样本上优化 = 在训练集上自评 = 过拟合。9 张多样噪声作留出验证集，
> 让「优化是否真的泛化」有据可依。（实测 N=9 是成本/判别力的合理平衡。）

### 步骤 4 · 触发迭代
- 凑满样本后自动启动；也可点头部「**开始优化**」手动触发。
- 系统创建新 prompt 版本并跑**最多 3 轮**：
  - 每轮 OCR 全部已确认样本、逐字段评分；达标（≥99.9%）即早停；否则只优化未达标字段，判官把关后重组新版本；
  - **准确率逐轮单调不降**：某轮变差自动丢弃、保留更好版本；
  - **留出门**：把 12 张切 train/val，只在 train 上优化、按 **val 泛化分**选版本（不新增 OCR 调用）。

### 步骤 5 · 看「优化过程」
头部「**优化过程**」tab：逐轮、逐字段查看优化前/后识别结果、与 GT 的 ✓/✗、准确率曲线。

### 步骤 6 · 激活发布
确认效果 → 「激活发布」→ API 变为**已发布**、对外可调用。需下线点「停用」（可再次激活）。

## 5. 工作区详解

工作区头部有 **3 个 tab** + 右侧 **2 个按钮**：

| 元素 | 作用 |
|---|---|
| **字段视图**（tab） | 编辑字段、上传样本、看识别结果（主工作区，左文档 / 中字段 / 右 JSON 三栏） |
| **优化过程**（tab） | 迭代每轮的逐字段优化对比、准确率曲线 |
| **新增技能**（tab） | 技能库：可复用识别规则片段的管理（见下） |
| **开始优化**（按钮） | 手动触发一次完整迭代（需样本达标） |
| **保存并生成 API**（按钮） | 把当前字段集保存生成 API |

### 「新增技能」tab（技能库）
技能 = 可复用的识别规则片段，挂到字段后注入该字段的识别 prompt。
- **私有技能**：仅本 API 可用。
- **全局技能**：**按国家共享**——一个 JP 全局技能只在 JP 的 API 技能库里出现，MY 的 API 看不到（通用/跨国技能可不绑国家）。
- 在此可：新建技能、设为全局、**挂到字段**、停用。
- 红线：**优化器不能写技能**，技能只能由人（管理员 / 用户）策展，或经「技能晋升」由管理员确认入全局库。

## 6. 字段级用户反馈

> 这是给迭代优化的「用户反馈提示」——**不是最终 prompt**，而是让优化器反思时知道你的期望。

两个入口：
1. **新增字段时**：「添加识别字段」表格里，每个字段行**下方**有一条反馈输入，**填完点别处自动保存**。
2. **双击编辑字段时**：编辑面板里「格式」下方、「保存」按钮上方有反馈框，**与本次修改一起保存**。

示例反馈：
- 「发票号要输出纯数字、去掉前缀」
- 「这个字段取右下角那个值，不是顶部那个」
- 「金额去千分位逗号」

保存后落入该字段的反馈，下次优化时作为该字段反思的上下文注入，引导识别规则朝你的期望调整。

## 7. 调用提取 API

### 7.1 创建 API Key
「设置」→「API Key」→「创建」。**明文密钥仅创建时显示一次**，请立即保存。

### 7.2 调用
```bash
curl -X POST "https://invoicase.cn/api/v1/extract/<api_code>" \
  -H "X-API-Key: sk-你的密钥" \
  -F "file=@/path/to/invoice.pdf"
```
- `<api_code>` 为该 API 的唯一编码（定制过程中不变）。
- 返回遵循全球输出契约的结构化 JSON（已去千分位、qty×price 校验、一行一项等）。
- 未激活（待验证 / 已停用）的 API 不对外服务。

## 8. 平台管理员功能

管理控制台（`/admin`）有 5 个 tab：

| Tab | 谁可见 | 作用 |
|---|---|---|
| **系统管理员** | 仅超级管理员 | 创建 / 重置 / 停用系统管理员 |
| **用户管理员 / 租户** | 平台管理员 | 创建租户 + 用户管理员、重置 / 停用 |
| **国家模板** | 平台管理员 | 审阅各国黄金种子 + 人工 GT；用当前模板「重新评测」看冲突字段 |
| **技能晋升** | 平台管理员 | 把反思反复建议的技能采收成候选，LLM 起草 → 管理员确认 → 晋升进全局技能库 |
| **技能洞察** | 平台管理员 | 选一个 API，看其优化诊断：每字段准确率轨迹、稳定/波动守护、已挂技能、编辑接受/拒绝 |

### 技能晋升（怎么用）
1. 选国家 → 看候选列表（每条 = 国家/字段 + 反思原文 + 跨租户/出现计数 + golden 参考分）。
2. 「**起草并晋升**」→ 模型（qwen-plus）起草技能正文 → 你**编辑**确认 → 写入**全局技能库**（按国家）。
3. 晋升门槛：**管理员确认是唯一硬门**；「跨租户 > 5」是自动推荐徽标（管理员可越级晋升）。

### 技能洞察（怎么用）
顶部**选一个 API** → 查看：
- 每字段**跨轮准确率轨迹**（小柱，按准确率着色）；
- **守护徽标**：pin（稳定达标）/ caution（波动回退）；
- **规则段**（迭代沉淀的识别规则）+ **已挂技能**；
- **编辑结果**（接受 / 拒绝 by 操作类型）。

## 9. 建议的测试场景（给同事）

> 走一遍主线，覆盖新交互。建议用一个 JP 或 MY 测试 API。

1. **新建 + 编辑字段**：新建一个国家模板 API；改一个字段名；把发票号设为 `number`；尝试改一个 🔒 锁定字段（应被拒/锁定）。
2. **字段反馈**：给某字段填反馈（新增行下方 / 编辑面板里），确认保存。
3. **样本 + 噪声门**：上传 3 张锚点并逐张「已审视」；横幅提示后批量上传 9 张噪声（计数器须正好 9 张才能上传）；确认自动启动迭代。
4. **优化过程**：迭代后看「优化过程」逐字段对比。
5. **新增技能**：在「新增技能」tab 新建一条技能 + 挂到字段；确认 JP 的全局技能不出现在 MY 的 API 技能库。
6. **激活 + 调用**：激活发布 → 建 API Key → curl 调 `/extract/<api_code>`。
7. **管理员**：用 admin 登录控制台 → 「技能晋升」起草晋升一条技能 → 「技能洞察」选该 API 看轨迹/守护/规则段。

测试时请重点反馈：交互是否符合直觉、文案是否清楚、保存时机是否合理、识别结果质量。

## 10. 已知限制 / 常见问题

| 现象 | 说明 / 处理 |
|---|---|
| 登录又被弹回 | token 过期，重新登录 |
| 普通用户验证码登不进 | 邮箱未被用户管理员开通，或验证码不是 `666666` |
| 看不到管理控制台 | 当前非平台管理员（仅 super/system admin） |
| 列表是空的 | 新租户初始无数据；本租户只看本租户数据 |
| 访问他人资源 404 | 跨租户隔离（故意 404，不暴露存在性），非数据丢失 |
| 改/删 🔒 锁定字段无效 | 设计如此：国家锁定字段不可增删改 |
| 噪声门要求 12 张 | 3 锚点 + 9 噪声；不足停在「等待样本」 |
| 提取 API 401 | `X-API-Key` 缺失/吊销，重新建 Key |
| 提取 API 不服务 | API 未激活，先「激活发布」 |
| 迭代「无提升」 | 单调守护保留了更好的旧版本，属正常 |
| 技能库为空 | 该国家暂无可引用技能（全局按国家隔离）；可新建或等管理员晋升 |
| MY 的 API 看不到某全局技能 | 它是别国（如 JP）的全局技能，按国家隔离，正常 |

### 11.2 优化机制开关（线上状态）

| 开关 | 线上 | 作用 |
|---|---|---|
| 留出验证门 / 噪声门 / 编辑纪律 / 技能库渲染 | **ON** | P1/P2 优化纪律 + 技能注入 |
