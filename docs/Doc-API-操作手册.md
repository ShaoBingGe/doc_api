# Doc API · 操作手册

> **Doc API** 是一个文档结构化提取平台：从一份国家模板出发，用 prompt 自迭代打磨字段识别规则，
> 把任意票据/文档变成稳定可调用的提取 API。
> 本手册面向三类使用者：**平台管理员**、**用户管理员（租户）**、**普通用户**。

## 1. 系统概览

| 维度 | 说明 |
|---|---|
| 产品形态 | Web 平台（管理 UI）+ 公有提取 API |
| 核心能力 | 国家模板 → 客户改字段 + 给样本 → prompt 自迭代 → 稳定提取 API |
| 后端 | FastAPI + SQLAlchemy + SQLite，端口 **8000** |
| 前端 | React + TypeScript + Vite，端口 **5173** |
| 两个入口 | **用户入口** `/login`、**管理员入口** `/admin/login` |
| 两套认证 | 管理 UI 用 JWT；提取 API 用 `X-API-Key` |
| 数据隔离 | **按租户隔离**：用户只能看本租户的 API / 文档 / Key / prompt / 迭代；平台管理员跨租户全可见 |

**心智模型一句话**：你不写识别规则，你只「改字段 + 传样本」，平台自动把规则迭代到稳定可用。

## 2. 安装与启动

### 2.1 环境要求

- Python 3.11+（建议 3.13）
- Node.js 18+ 与 npm
- （生产）PostgreSQL；（原型）默认 SQLite，无需额外安装

### 2.2 启动后端（端口 8000）

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

启动时会自动：建表、**创建超级管理员**（默认 `admin` / `666666`）。
打开 `http://localhost:8000/docs` 可见交互式 API 文档。

### 2.3 启动前端（端口 5173）

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:5173`。未登录会自动跳转到登录页。

### 2.4 关键环境变量（`backend/.env`，可选）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./data/apianything.db` | 换成 `postgresql://…` 即上生产库 |
| `SECRET_KEY` | 占位值 | **生产务必改**：JWT 签名密钥 |
| `SUPER_ADMIN_USERNAME` / `SUPER_ADMIN_PASSWORD` | `admin` / `666666` | 安装时创建的超级管理员 |
| `NORMAL_USER_LOGIN_CODE` | `666666` | 普通用户登录验证码（接邮件下发前的固定值） |
| `GEMINI_API_KEY` | 空 | 生产 OCR 用；为空则走 mock |
| `LLM_FALLBACK_CHAIN` | 空 | 反思/优化的 LLM 失败链，如 `gemini\|gemini-2.5-flash;mock\|` |

## 3. 账号、角色与登录

### 3.1 四种角色

| 角色 | 谁创建 | 登录方式 | 核心权限 |
|---|---|---|---|
| **超级管理员** super_admin | 安装时自动 | 账号 + 密码 | 全部：建系统管理员、维护用户管理员、模板优化平台 |
| **系统管理员** system_admin | 超级管理员 | 邮箱 + 密码 | 维护用户管理员、模板优化平台 |
| **用户管理员** tenant_admin | 超级/系统管理员 | 邮箱 + 密码 | 管理本租户普通用户、改自己密码、用产品 |
| **普通用户** normal_user | 用户管理员 | 邮箱 + 验证码 | 仅使用客户产品 |

### 3.2 两个登录入口

- **用户入口** `http://localhost:5173/login`
  - Tab「普通用户」：邮箱 + 验证码（默认 `666666`）。
  - Tab「用户管理员」：邮箱 + 密码。
- **管理员入口** `http://localhost:5173/admin/login`
  - 超级管理员 / 系统管理员：账号 + 密码。登录后进入「管理控制台」`/admin`。

### 3.3 默认 / 示例账号

| 角色 | 账号 | 密码 / 验证码 |
|---|---|---|
| 超级管理员 | `admin` | `666666` |
| 系统管理员（示例） | `sysadmin1@apianything.io` | `sys123456` |
| 用户管理员（示例，租户 Acme 公司） | `admin@acme.com` | `acme123456` |
| 普通用户（示例，Acme 公司） | `user1@acme.com` | 验证码 `666666` |

> 生产环境请在首次登录后立即修改默认密码，并改 `.env` 中的默认凭证与 `SECRET_KEY`。

### 3.4 数据隔离与可见范围（多租户）

所有数据接口都**强制登录**（管理 UI 走 `Authorization: Bearer <JWT>`），并按**租户**隔离：

| 身份 | 能看到的数据 |
|---|---|
| 用户管理员 / 普通用户 | **仅本租户**的 API、文档、API Key、prompt 版本、迭代过程 |
| 超级管理员 / 系统管理员 | **跨租户全部**用户数据、文档、prompt 与迭代过程 |

规则与细节：
- 每条数据创建时按创建者的租户盖上 `tenant_id`；平台管理员创建的数据归入「平台桶」（仅管理员可见）。
- 跨租户访问他人资源一律返回 **404**（不泄露存在性），而非 403。
- **公有提取端点** `/api/v1/extract/` 仍走 `X-API-Key`，不受 JWT 隔离影响（密钥本身已绑定到具体 API）。
- 同一租户内的用户管理员与普通用户**共享**该租户的数据。

> 升级既有库：后端启动时会幂等地为数据表补 `tenant_id` 列（原型 SQLite 用轻量 `ALTER`；生产 PostgreSQL 建议走正式迁移）。

## 4. 平台管理员操作

进入 `/admin/login` 登录后到达「管理控制台」。

### 4.1 管理系统管理员（仅超级管理员）

1. 顶部 Tab「系统管理员」→ 右上「创建系统管理员」。
2. 填邮箱、初始密码、显示名（可选）→ 创建。
3. 列表里可对每个系统管理员：**重置密码** / **停用·启用**。
4. 系统管理员**不能**再创建系统管理员（仅维护用户管理员）。

### 4.2 管理用户管理员与租户（超级 + 系统管理员）

1. Tab「用户管理员 / 租户」可见所有租户卡片（含管理员数、普通用户数）。
2. 右上「创建用户管理员」：填**租户名称** + 管理员邮箱 + 初始密码。
   - 租户名称不存在则新建租户；已存在则复用并为其再加一个管理员。
3. 列表里可对每个用户管理员：**重置密码** / **停用·启用**。

### 4.3 进入模板优化平台

顶部「模板优化平台」按钮 → 国家模板字段总览 / OCR 优化器视图（详见 §8）。

### 4.4 国家模板 / 黄金种子审阅页（Tab「国家模板」）

管理控制台新增「**国家模板**」Tab（仅平台管理员可见），用于审阅各国模板的黄金种子与人工复核数据：

1. 顶部选择**国家**（如 MY）与模板**种类**（目前为 invoice）。
2. 主体把该国**黄金种子样本纵向排列**，每行 **样本 PDF 在左、数据集在右**：
   - 右侧默认平铺**人工复核确认过的标注数据（GT）**。
3. 点右上「**重新评测**」→ 用**当前国家模板 prompt** 对黄金集跑一遍 OCR（按需触发、结果缓存）：
   - 识别结果**与标注一致**的字段：**不加任何视觉效果**；
   - **有冲突**的字段：琥珀色高亮，并**并排展示「标注 GT」与「最新模板识别值」**（参考字段优化对比的设计）。
4. 评测为**按需 + 缓存**：进入页面读最近一次缓存结果；未评测过则显示「尚未评测」，只看 GT。
   Gemini 不可用时评测会优雅失败（不报 500），GT 视图始终可用。

> 用途：直观看出「当前国家模板」在黄金集上哪些字段还识别不准，指导平台侧改模板 / 机器。

## 6. 核心业务流程：定制一个提取 API

> 这是产品的主线。目标：把一份国家模板，定制成贴合你票据的稳定提取 API。

### 步骤 1 · 从国家模板新建 API

1. 首页右上「定制新 API」或「订阅模板」。
2. 选择国家模板（如 MY 马来西亚发票）→ 系统按模板生成初始字段集，进入**工作区**。

### 步骤 2 · 编辑字段

在工作区中间「字段识别」栏：
- **改名 / 改描述**：直接编辑字段。
- **新增字段**：填字段名 + 一个样例值，系统会用 LLM 反思扩展出完整识别规则。
- **删除字段**：点字段右侧删除图标（与编辑面板「删除此字段」效果一致，所有样本 + 优化器同步生效）。

### 步骤 3 · 上传样本并「已审视」

1. 上传**至少 3 个**真实样本（PDF/图片）。
2. 逐个核对识别结果，对每个字段确认或修正后点「已审视」——
   被审视/修正的值即成为 **Ground Truth（人工真值）**，是后续迭代的评分基准。
3. 样本数不足时，系统会停在「等待样本」，补足并审视后自动继续。

### 步骤 4 · 保存生成 → 触发迭代

1. 点「保存并生成新 API」→ API 进入**待验证**状态（列表可见）。
2. 系统在该 API 上创建新 prompt 版本并跑**最多 3 轮迭代**：
   - 每轮先用当前版本 OCR 全部已审视样本、逐字段评分；
   - 达标（≥99.9%）即早停；否则只优化未达标字段，判官把关后重组新版本；
   - **准确率逐轮单调不降**：若某轮反而变差，自动丢弃、保留更好的版本。

### 步骤 5 · 查看「字段优化对比」

在「优化过程」面板展开「字段优化对比」可逐样本查看：
- 每个字段的**优化前 / 优化后**识别结果；
- 与人工 GT 的匹配标识（✓/✗）；
- 「只看有变化」筛选：变好 / 变差 / 新增字段。

### 步骤 6 · 激活发布

确认效果后点「激活发布」→ API 变为**已发布**，对外可调用。
如需下线点「停用」（可再次激活）。

## 7. 调用提取 API

### 7.1 创建 API Key

「设置」→「API Key」→「创建」。**明文密钥仅在创建时显示一次**，请立即保存。

### 7.2 调用提取端点

```bash
curl -X POST "http://localhost:8000/api/v1/extract/<api_code>" \
  -H "X-API-Key: sk-你的密钥" \
  -F "file=@/path/to/invoice.pdf"
```

- `<api_code>` 为你定制 API 的唯一编码（定制过程中不变，便于集成）。
- 返回一份遵循全球输出契约的结构化 JSON（已去千分位、qty×price 校验、一行一项等）。
- 未激活（待验证/已停用）的 API 不对外服务。

## 8. 模板优化平台与黄金种子

> 仅平台管理员可用。这条「黄金回路」用于**改进国家模板本身 + 守护优化机器**，
> 与客户回路完全隔离：不接入任何客户路径、不按客户数消耗 token。

### 8.1 国家模板

- 模板文件位于仓库根：`<COUNTRY>_invoice_prompt.yaml`（如 `MY_invoice_prompt.yaml`），**只读**。
- 结构：Part 1 国家事实 + Part 2 字段语义（按国家） + Part 3 输出契约（指向全球平台资产）。
- 改国家事实/字段语义改 Part 1/2；改输出装配规则改 `assets/global_output_contract.yaml`（走 PR）。

### 8.2 黄金种子集合（平台冻结）

- 位置：`backend/app/ocr_optimizer/eval/golden_set/<COUNTRY>/`。
- 要求：每个种子的**每个字段都有人工 GT、无空值**（避免假识别放行）；判定标准为**完全相等**。
- 用途：平台改 composer / skill / reconciler / 输出契约时，离线跑严格 A/B，确认「严格分不下降」才放行。

### 8.3 平台回归 CLI

```bash
cd backend && source .venv/bin/activate
# 在冻结黄金集上随机抽 ≤5 篇同结果集种子做严格批跑
python -m app.ocr_optimizer.eval.run_golden_batch --country MY --size 5
```

> 红线：黄金门槛只在平台改机器时离线运行，**永不**接进客户迭代；客户 prompt 过不过由客户自己的样本（模糊评分）决定。

### 8.4 在线审阅（管理控制台「国家模板」Tab）

除了上面的 CLI，平台管理员也可在 UI 上直接审阅黄金种子与冲突——见 §4.4。
该页的「重新评测」与 CLI 同源（复用同一评测 harness），区别只是：UI 评测**全量逐字段**展示「GT vs 最新模板识别值」，CLI 做的是**可比批跑**的严格分对比。

## 9. 常见问题与排障

| 现象 | 可能原因 / 处理 |
|---|---|
| 登录后又被弹回登录页 | token 过期；重新登录。检查后端是否在 8000 运行 |
| 普通用户用验证码登不进 | 该邮箱未被用户管理员开通；或验证码不是 `666666` |
| 管理控制台 / OCR 优化器入口看不到 | 当前角色非平台管理员（仅 super/system admin 可见） |
| 登录后 API / 文档列表是空的 | 正常：新租户初始无数据；本租户只看本租户数据。要看历史测试数据用对应账号（如 `admin@acme.com`） |
| 数据接口返回 401 | 管理 UI 请求缺少有效 JWT；重新登录获取 token |
| 访问他人资源返回 404 | 跨租户访问被隔离（故意返回 404 不暴露存在性），并非数据丢失 |
| 「国家模板」页一直「尚未评测」 | 还没点过「重新评测」，或 Gemini 不可用导致评测失败；GT 仍可正常查看 |
| 系统管理员建系统管理员报 403 | 设计如此：仅超级管理员可建系统管理员 |
| 保存后字段集丢失 / 识别结果异常 | 确认样本已正确「已审视」；查看「优化过程」面板的逐轮结果 |
| 提取 API 返回 401 | `X-API-Key` 缺失或已吊销；重新创建 Key |
| 提取 API 返回 410/不服务 | API 未激活（待验证/已停用）；先「激活发布」 |
| OCR 不出结果 | `GEMINI_API_KEY` 未配置或网络不通；系统会降级到 mock，不报 500 |
| 迭代「无提升」 | 单调守护保留了更好的旧版本，属正常（不是失败） |
| `npm run build` 报 TS 错误 | 开发用 `npm run dev` 即可；生产构建的类型问题单独修 |
