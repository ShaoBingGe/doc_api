# 设计与开发计划 · MY 模板分层瘦身（对照 JP 格式的取舍）

> 状态：待执行（依赖前置门 P0/P1，见 §4）
> 日期：2026-08-28 ｜ 分支 `feat/schema-passed-to-model` 系列工作的后续
> 结论先行：**应该瘦身，但不应照搬 JP 格式** —— 做「分层瘦身」：
> 字段级细则迁去 description（单一事实源），文档级裁决必须留正文。
> 预期收益是**输入成本 −30%~40% 与维护性**，不是时延，也不是准确率。

## 1. 两个模板的形态对比（实测数字）

| | MY 7_13 | JP jp-v8 |
|---|---|---|
| 正文 | **13,998 字符** | 2,662 字符 |
| schema description 合计 | 7,130 字符 | 3,159 字符 |
| 规则主承载 | 正文（description 大量镜像正文） | **description**（正文只留切分/计数/通用约束） |
| 对 PASS_SCHEMA_TO_MODEL 的依赖 | 弱（关了也能跑，这是历史缺陷逼出来的） | 强（关了准确率掉到 1/2~1/3，实测） |

## 2. 为什么「迁」是对的（本会话攒下的硬证据）

1. **description 在输入侧是免费的。** 实测 `response_schema` 不计入 prompt
   token（JP A/B 中两模式输入 token 逐份完全相同）。同一条规则放正文要花钱、
   放 description 不花钱——迁移直接省掉这 ~5.5k 字符的输入成本。
2. **description 现在真的生效且效果被验证过。** JP：+100%~187%；MY：Phase 2/3
   开≥关。规则放 description 不再是死字。
3. **双写会漂移。** §1.34 已经要求「改动请两处同步」——人工同步纪律迟早失守。
   单一事实源消除这类债。
4. **schema 一通已经连续暴露 3 处双写债**（Tax Invoice「等」字、BRN 括号旧号、
   v6 负号）——每一处都是「description 与正文各说各话」的产物。

## 3. 为什么「不能照搬 JP」（同样是硬证据）

1. **v6.1 实验直接否决了"删结构性复述"**：删掉 2,156 字符的「输出字段清单」
   （键名+类型+**enum 内联**）后准确率 51/54→48/54。response_schema 的 enum 只保证
   **输出值合法**，不提供**如何在候选间选择**的语义引导——composer 渲染的紧凑
   字段树（含 enum）必须留在正文。
2. **切分与分类裁决无处可去**：G 类段落（≈6,000 字符）是文档级/跨字段推理，
   schema 是字段级结构，承载不了它们。JP 正文留的恰恰也是这两类——
   所以正确说法是「MY 收敛到 JP 的**分层原则**」，不是「MY 压到 JP 的长度」。
3. **时延不会变好**：v6.1 实测输入 −17% 换来耗时 +0.5s——时延由输出 token
   与网络主导。「提升识别效率」的真实内涵是**输入成本与可维护性**，
   预先把预期摆正，避免拿时延验收。
4. **JP 的准确率不构成"瘦身更准"的证据**：两国样本集、GT 口径不同，0.79 vs MY
   的数字不可直接比。瘦身的准确率目标是**不降**（单调门），不是提升。

## 4. 两个前置门（不过门不动手）

**P0 · 生产开关已灰度稳定。** description-only 的规则在开关关闭时是死字。
必须等 Phase 4（腾讯云灰度 `PASS_SCHEMA_TO_MODEL=true` 观察 24–48h）通过后
才能开始迁移——否则一次回退（.env 改 false）就等于删掉 MY 39% 的规则。

**P1 · qwen 回退通道补文本渲染。** 这是**最硬的架构约束**：DashScope 视觉模型
不支持 response_schema，qwen 收到也忽略。当前 MY 在 qwen 上能跑好，正因为规则
在正文里；迁移后一旦主力熔断切到 qwen 备份，**迁走的规则全部消失**。
处置：在 processor 层做「按 provider 渲染」——provider 不支持结构化输出时，
把 schema description 自动渲染成文本附录拼进 instruction（qwen 付这笔 token，
Gemini 不付）。单一事实源仍在 schema，两个 provider 各取所需。
JP 模板在 qwen 部署上同样吃这个修复的红利。

## 5. 多轮迭代计划

> 原则沿用仓库惯例：每轮独立可交付、判据前置、单调门（任何字段不降即回退
> 该轮）、独立提交、可随时停。版本号 7_14 起逐轮递增。
> 每轮验证复用现成基建：三样本（S1/S2/S3 ×3 轮）+ 黄金集（≥2 seed，
> `--schema auto`）+ 必要时 tpl7 七判据；qwen 侧用 S1+S3 各 1 轮抽验。

### R0 · 基线冻结与迁移清单（零模型调用）
- 记录 7_13 基线：输入 token（三样本逐份）、黄金集 4 seed 分数、三样本 18 判据；
- 把 §1 的分类表落成逐条规则的迁移清单（每条：正文位置 → 目标 description
  字段 → 是否已有镜像 → 差异点），差异点先对齐（以更严的一版为准）；
- 产出：`eval_samples/schema_ab/slim_inventory.md` + 基线 json。

### R1 · P1 前置——qwen 文本回退通道（平台代码，非模板）
- `QwenProcessor.process_document`：收到 `runtime_config["response_schema"]`
  时渲染 description 附录（字段名 · 类型 · enum · description）拼进 instruction；
- 测试：qwen 收到 schema 时 instruction 含附录、Gemini 行为零变化、
  开关关闭时两 provider 均无附录；
- 真机：S1/S3 各 1 轮走 qwen（本地有 key），字段结果与当前正文版持平；
- 这轮独立有价值（JP 在 qwen 上立刻受益），不依赖后续轮次。

### R2 · 试点迁移 §1.34（7_14）——最低风险
- 507 字符、description 逐句同款，**纯删除正文段**；
- 门：三样本 18 判据全过 + 黄金 2 seed 不降 + qwen S1 抽验 nameOfInvoice/unitPrice 不丢；
- 通过 → 删除 yaml 注释里的「两处同步」义务（单一事实源达成第一例）。

### R3 · 迁移 §1.3 税号细则（7_15）——高价值高风险
- 2,150 字符。正文保留 3 行裁决摘要（「TIN/SSM/SST 三者严禁混用；票面多处
  出现相互比对」），细则（格式、逐位核读、混淆对、禁取清单）以 description 为准；
- 迁移时**合并两版差异**（正文与 description 各有对方没有的句子）；
- 门：黄金集用含 BRN 样本的 seed + S1 的 BRN 判据（`1298487-V` 这类括号旧号
  是已知高危点，Phase 2 刚在这摔过）；qwen 抽验 billFrom* 三字段。

### R4 · 迁移 §1.35 + §1.36 字段级部分（7_16）
- §1.35（638）→ 明细行 schema；§1.36.2 字段标签表中"纯字段查找词"部分 +
  §1.36.3 月份 + §1.36.4 单位 → 对应字段 description；
  **1.36.1 标题裁决与 PENYATA→other 留正文**（分类层）；
- 门：三样本 + 马来语样本 22 判据复跑（两台…改为本地双 provider）+ 黄金 2 seed。

### R5 · §1.2 半瘦身 + 收口（7_17）
- 日期格式细则并入 invoiceDate description，多币种 MYR 规则留正文（全局事实）；
- 终验：黄金 4 seed + 三样本 ×3 + tpl7 七判据 ×3 + 25 页样本 1 轮；
- 度量收口：对比 R0 基线的输入 token（预期 −30%~40%）、准确率（要求全字段不降）；
- 文档收口：更新 `prompt-system.md`（新增「国家模板分层规范」：正文=切分/
  分类/全局事实/自检 + 紧凑字段树；description=字段级 where/what/format/禁取；
  新国家一律按此写，JP 是参考实现）；MY remark 记录瘦身谱系。

### 每轮的回退约定
单调门失败 → `git revert` 该轮模板提交即可（模板是纯数据，无代码耦合）；
线上（若已部署）用 seed 刷新机制回灌上一版 yaml，无需回代码。

## 6. 预期与不预期

| | 预期 |
|---|---|
| 输入 token / 成本 | **−30%~40%**（≈5.5k 字符不再随每次调用付费） |
| 维护性 | 单一事实源，消除三处已知双写债的再生土壤 |
| 准确率 | **不降**（单调门保证；不承诺提升） |
| 时延 | **基本不变**（v6.1 实测；不要拿它验收） |
| qwen 备份质量 | R1 后**提升**（首次拿到 description 规则） |
