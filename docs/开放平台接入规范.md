# 开放平台接入规范

> 面向对接方的调用约定。契约细节见 [open-api-piaozone.md](./open-api-piaozone.md)，
> 本文只讲**怎么调才对、怎么调会踩坑**。
>
> 最后更新：2026-08-26

---

## 一、五分钟上手

```
① POST /base/oauth/token                                   → access_token（36 小时）
② POST ~/ai/knowledge/nlpService/document/analyze/async     → taskId（毫秒级返回）
③ POST ~/ai/knowledge/nlpService/tasks/query                → 轮询取结果
```

所有接口 **HTTP 恒为 200**，成败看响应体的 `errcode`（`"0000"` 为成功）。
路径**不带 `/api/v1` 前缀**。

---

## 二、四条硬规矩

### 1. access_token 必须缓存，有效期 36 小时

实测某日：**353 次取 token 换 137 次业务请求**，2.6 : 1。这是纯浪费。

```
拿到 token → 本地缓存 → 到期前 30 分钟再换
```

不要每次业务调用都换新 token。

### 2. 优先用异步接口，别拿同步接口打并发

| | 同步 `~/overseaInvoice/extraction` | 异步 `~/document/analyze/async` |
|---|---|---|
| 返回时机 | 识别完才返回（几十秒到几分钟） | **10 毫秒**返回 taskId |
| 并发超限 | 排队最多 120 秒，超时返 `5000 服务繁忙` | 不受并发闸影响，落盘即入队 |
| 适用 | 单张、要立等结果 | **批量、任何有并发的场景** |

服务端并发上限是 6 个文档同时识别。同步接口在这个上限之上会排队，
排不进去就被拒；异步接口只要提交成功就一定会被处理。

### 3. 轮询要在**终态**停止 —— `FAILED` 也是终态

`status` 只有三个值：

| status | 含义 | 该怎么做 |
|---|---|---|
| `PENDING` | 排队中或识别中 | 继续轮询 |
| `COMPLETED` | 成功，取 `result` | **停止轮询** |
| `FAILED` | 失败，看 `errorMessage` | **停止轮询**，别再等 |

实测有客户端把已经 `FAILED` 的任务反复轮询了数分钟——只认 `COMPLETED`
作为终止条件是错的。

**建议节奏**：首次等 3 秒，之后每 2 秒一次。
**批量查询**：一次最多 10 个 taskId，比逐个轮询省 10 倍请求。

### 4. `result` 是**字符串**，需要自己解析

```json
{ "result": "{\"errcode\":\"0000\",\"data\":[...]}" }
```

拿到后要 `JSON.parse()` / `json.loads()` 一次，里面才是识别结果。
仅当 `status == "COMPLETED"` 时有值。

## 三、文件要求

提交时会**当场校验**，不合格直接返回 `A0700` 且**不发 taskId**。
与其发个 taskId 让你白轮询几分钟，不如立刻告诉你哪儿不对。

| 项 | 要求 |
|---|---|
| 格式 | `.pdf` / `.png` / `.jpg` / `.jpeg` / `.xlsx` |
| 大小 | ≤ 20 MB |
| 内容 | 必须**真的是该格式** —— 改后缀的文件会被拒 |
| 完整性 | 不能截断/损坏 |
| 图片尺寸 | 单边 ≥ 16 像素 |

**最常见的踩坑**：把别的格式改名成 `.jpg`。我们校验文件头，不看后缀。
错误信息会说明实际的文件头是什么，方便你定位。

> 已知边界：极小的退化图片截断后可能通过校验、到模型那里才失败。
> 这类任务会走完重试并标 `FAILED`，`errorMessage` 里有模型的原始报错。

## 四、错误码

### 异步接口（A 系）

| errcode | 含义 | 怎么办 |
|---|---|---|
| `0000` | 成功 | — |
| `A0301` | 未授权 | token 无效/过期，或无权用该 templateId |
| `A0410` | 必填参数为空 | 没传文件，或 `taskIds` 为空 |
| `A0426` | 批量超限 | 一次查询超过 10 个 taskId |
| `A0700` | 文件不可用 | 看描述修文件，**不要重试同一个文件** |
| `C0110` | 识别管线出错 | 可重试 |
| `1999` | 其他失败 | 含队列满，稍后重试 |

响应里另有 `legacyErrcode` 字段，是内部排查用的对照，**对接方不必解析**。

### 同步接口（4xxx 系）

同步端点沿用既有的 `4001`~`4008` / `5000`，与异步是两套码，
这是历史契约，不做统一。`5000` 兼作"服务繁忙"与"识别失败"，看描述区分。

## 五、查不到 taskId 怎么办

查询结果是 **Map**（key 为 taskId）。查不到的 taskId **不会出现在 map 里，
也不报错**——这包括两种情况，服务端刻意不区分：

- 该 taskId 不存在（或已过期，任务保留 **10 天**）
- 该 taskId 属于**别的 client**

不区分是为了不泄露"这个 id 是否存在"。所以客户端要自己处理"某个 taskId
没在返回里"的情况，别假设一定有。

## 六、当前服务能力

| 项 | 值 |
|---|---|
| 并发识别 | 6 个文档 |
| 吞吐 | **约 5 次/分钟**（受上游模型配额限制） |
| 单张耗时 | 单页约 10–20 秒；6 页多票据约 20–25 秒 |
| 队列上限 | 全局 200 个，单 client 50 个 |
| 任务保留 | 10 天 |

吞吐上限来自上游模型配额，加并发解决不了——实测并发从 3 提到 6，
吞吐从 3.9 次/分变成 3.2 次/分，没有提升。**批量场景请用异步接口 +
合理轮询**，不要靠加并发压。

## 七、两套环境

两台实例**凭证已统一**，同一套 `client_id` / `client_secret` 通用。

| | 地址 | 位置 | 模型 |
|---|---|---|---|
| 新加坡 | `https://docai-sg.test.piaozone.com` | 新加坡 | `gemini-3.5-flash` |
| 境内 | `https://invoicase.cn` | 阿里云境内 | `qwen3-vl-flash` |

就近选择：境外调用方用新加坡节点，境内调用方用 invoicase.cn。
**不要跨区域调用**——实测新加坡节点访问境内模型服务延迟 411ms（境内是 3ms），
会让识别慢一个数量级。

请使用轮询获取结果。回调（含 2/10/30 分钟重试）计划在下一期实现，
届时会另行通知。
